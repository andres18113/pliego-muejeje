# Offers API — functional integration

- `GET /api/v1/catalog/offers`: public `PageResponse<CatalogEditionSummaryResponse>`; filters `productType=PHYSICAL|EBOOK|AUDIOBOOK`, category slug and optional legacy format; `sort=RELEVANCE|ENDING_SOON|PRICE_ASC|PRICE_DESC` (default RELEVANCE), page >= 0, pageSize 1–50. Empty and out-of-range pages preserve the authoritative total count. Inactive categories retain catalog 409 behavior; unknown categories return empty results.
- `GET /api/v1/catalog/offers/filter-options`: current applicable `productTypes[{code,label,count}]`, `categories[{slug,name,count}]`, `sorts[{code,label}]`, `totalCount`, `endingSoonDays=3`, `timezone=America/Guayaquil`. Counts are decimal integer strings. Facets are global across current public offers.
- Existing catalog summary/detail responses have nullable `offer`: `{offerId,originalPrice,effectivePrice,discountAmount,savingsAmount,savingsPercent,startsAt,endsAt,daysRemaining,endingSoon,offerCopy,terms}`. Amounts and percentage are decimal strings with two places; daysRemaining is integer, endingSoon boolean; optional copy/terms are nullable. Public timestamps include Ecuador offset. Edition `price` always equals effectivePrice while an offer applies.
- `GET /api/v1/cart` uses `pliego.fn_cart_offer_quote(actor)` and exposes `originalSubtotal`, `savingsTotal`, `currentSubtotal` at cart level; each item adds `originalPrice`, `unitSavings`, `originalSubtotal`, `lineSavings` alongside `currentPrice` and `currentSubtotal`. All amounts are database-authoritative decimal strings with two places, including physical quantities greater than one, eBooks and audiobooks. Existing `subtotal` remains the discounted subtotal; `totalCurrent` and `total` include the database tax and shipping amounts. Neither Java nor the frontend recomputes these values. The legacy `fn_cart_quote` contract remains unchanged.
- `PUT /api/v1/admin/editions/{editionId}/offer`: ADMIN-only; `{offerPrice,startsAt,endsAt,offerCopy?,terms?}`; 204. Offer price must be positive and below the base price; valid RFC3339 times must delimit a nonempty interval. Optional authored offerCopy max1000 and terms max5000 characters. Replaces the edition's unique offer. No automatic campaign text.
- `DELETE /api/v1/admin/editions/{editionId}/offer`: ADMIN-only idempotent deactivation; 204 for an existing edition. Edition absence uses existing P2041 mapping; malformed/domain arguments use existing validation/P1001 mappings. Error messages remain Spanish.

PostgreSQL owns current unit prices in catalog filters/sorts/facets, favorites, cart quote, checkout and immutable order snapshots. Frontend code may format returned values and render states; it must not calculate discounts, savings percentage, calendar counts, offer eligibility, ranking or taxes. No offer/discount inputs are accepted from customer checkout.

Validation: `offers_gate.sql`, `offers_concurrency.py`, `offers_http_gate.py`, `cart_offer_projection_gate.sql`, focused catalog/cart/OpenAPI and JDBC mapping tests, plus existing digital/monetary/catalog/checkout gates. The offer-aware cart projection requires Flyway through V051.
