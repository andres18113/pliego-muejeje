Status: draft for independent operator review. Workstreams A/B/C are local;
production changes require a separate decision. `<evidence>` means the private,
git-ignored `.release-evidence/2026-11-04-vps-audit/` directory. Raw files are not
publication artifacts and must remain private.

executed under the no-VPS/no-production-traffic limit. Runs extend into 2026-11-05 UTC.

### Observability qualification

The default `application.yml` remains byte-identical, with management port `-1`.
The explicit `observability` profile binds management to loopback 8081, allows
only health, metrics and Prometheus, disables other endpoint access/discovery/JMX
exposure, hides health details and enables the Tomcat MBean registry. The
application connector retains anonymous 401/authenticated 404 for management
paths. Real connector tests and the packaged benchmark listener capture prove
the separation; no production proxy or listener was changed.

The review reproduced an unsafe override before the fix: observability with a
shared positive connector and an external configuration omitting the management
address served anonymous management health on the application connector. The
corrected profile now fails startup unless an explicit enabled management port
differs from the configured application port and a literal loopback management
address is present. Validation runs after ConfigData and again before bean
binding; arbitrary hostnames are rejected without DNS lookup. The permitAll
matcher is both EndpointRequest for the three allowlisted endpoints **and**
`request.getLocalPort()` matching the actual initialized management connector.
Actual server events, not overrideable `local.*` properties or forwarded headers,
establish that boundary. Invalid/startup/default/live-port tests are in
`<evidence>/instrumentation/review-corrections/`; production YAML remains `-1`.

HTTP URI tags use templates; twelve unknown paths collapse to `/**` and twelve
edition IDs to `/api/v1/catalog/editions/{editionId}`. Prometheus HTTP buckets are
exactly 100/300/800/1500/3000 ms plus infinity. SSE active/opens/rejections/closes,
deferred reads and successful sends use only bounded `resume`, `reason`, `kind`
tags. Batch size is a pressure signal. True backlog/time lag is omitted because
the existing read result lacks timestamps/tail and global cursor gaps include
invisible events; inventing a lag or adding queries would be misleading.

Prometheus registry 1.17.2 and six client 1.7.0 JARs add 2,444,860 uncompressed
archive bytes (2.33 MiB), not that amount of RSS. Boot manages versions; the
pull exporter initiates no external push. Registry allocation can still exist
with the management profile off. [Proposed ADR 0059](../adr/0059-opt-in-loopback-observability.md)
describes an SSH-tunnel scrape first, or one measured lightweight agent sending
to a reviewed hosted backend; no heavyweight VPS monitoring stack is proposed.

With the profile OFF, a normal-JIT cold-start heap snapshot contains one
Prometheus registry and 110 registered meters. MAT dominator analysis measures
104 bytes shallow size and 17,408 bytes (17 KiB) retained exclusively by that
registry instance. This excludes shared objects also retained by Spring/global
registries/services, class/metaspace/code-cache/native costs and later URI
cardinality; it is not the full incremental dependency overhead or an upper
bound. No HTTP, DB/provider calls or scheduled work ran in this private probe.
Same-snapshot map counts and OQL output, probe/JAR identity and exact commands
are in `<evidence>/root/review-corrections/registry-profile-off.md` and its raw
HPROF/query references. ADR 0059 records the measured scope and limitations.

Final backend command: `taskset -c 4-7 mvn -B -ntp

with mail/R2 credentials removed and those services disabled. **Latest security-review gate: exit 0, 785 tests, 746 executed/passed, 39 skipped,
zero failures/errors.** All 34 startup/port-boundary/default/live-profile tests
